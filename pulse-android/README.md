# Pulse 遥控 · Android App

一个**极薄的壳**，里面装的还是官方 DeepSeek Harness 界面。它不是重写的客户端——官方界面才是功能全集，
所以手机拿到的是真·官方界面，官方以后加的功能手机自动就有。

外壳只做三件浏览器做不到的事：

1. **信任你自己服务器的自签证书**（证书内置在 App 里）
2. **保持一条到 Pulse 的长连接**，用来收锁屏通知
3. **有自己的图标、全屏、没有地址栏**

## 这样做的直接结果

| 你的顾虑 | 结果 |
|---|---|
| 买域名 | **不需要**。直接连 `https://YOUR_HOST` |
| 备案 | **不涉及**。腾讯云的未备案拦截查的是域名，裸 IP 不受影响 |
| 证书续签 | **不需要**。内置的证书有效期到 **2036 年**，装进去就不会再因为证书过期弹错 |
| 推送服务账号 | **不需要**。不用 Firebase、不用华为/小米推送、不用极光，没有任何第三方在链路上 |

代价是：需要**一次**手动设置后台保活（见下），以及桌面证书那点电量开销。

## 前提条件：手机的系统 WebView 必须够新

官方客户端的外壳第一行就是：

```js
globalThis.__DSH_BOOT_READY__ ??= Promise.withResolvers()
```

`Promise.withResolvers` 要 **Chrome 119+**（2023 年 11 月）。这是**实测出来的**，
不是猜的——`dsh-remote-pulse/scripts/verify-engine-floor.mjs` 会扫描服务器实际下发的
外壳和客户端包，算出真正的最低版本，并和 App 里声明的那个数对比。

```
外壳 HTML      : Chrome 119+   (Promise.withResolvers)
客户端包       : Chrome 119+
实测下限       : Chrome 119+
App 里声明的   : Chrome 119+
一致
```

**低于这个版本会白屏，而且界面上没有任何错误提示**——所以 App 启动时会先自己读一次 WebView 版本，
不够就直接显示一段能照做的话（告诉你更新「Android System WebView」），而不是让你对着白屏发呆。

> 这条前提是官方 DSH 的属性，不是这个 App 的。官方将来升级到更新的语法，下限会跟着抬高——
> 到时候跑一下 `verify-engine-floor.mjs` 就知道，不用等手机上白屏才发现。

## 移动外壳：手机端不再照搬桌面布局

手机端跑的还是官方客户端，但外面加了一层**为拇指设计的外壳**。

### 页面层（注入到页面里）

| 部件 | 说明 |
|---|---|
| **侧栏 → 抽屉** | 官方那个常驻侧栏被移到屏幕外，汉堡按钮开合，带遮罩 |
| **汉堡按钮** | 左上角，拇指够得到 |
| **底部圆形「+」** | 右下角，点它触发**官方的**添加入口 |

关键设计：**自有 UI 全部挂在 `#root` 外面**。官方是 React 应用，往它的树里插东西会被下一次重渲染抹掉；挂在 `<body>` 上并用 `position: fixed`，React 永远不会碰。

定位用**语义前缀**而不是哈希：官方类名形如 `_splitCell_17p4l_32`，哈希每次构建都变，但 `[class*="_splitCell_"]` 不会失效。添加入口连语义前缀都没有，所以按**可访问名称**（`上传文件` / `添加文件` / `附件`）找——那属于界面契约，不是实现细节。

### 上传面板（App 原生）

点「+」→ 官方添加入口 → App 拦截文件选择器 → 弹出**原生**三格面板：

| 格子 | 拉起什么 |
|---|---|
| **拍照** | 系统相机，照片直接写进 App 缓存 |
| **照片 / 视频** | `ACTION_GET_CONTENT` + `EXTRA_MIME_TYPES={image/*,video/*}`，任何版本都能解析，不需要存储权限；Android 13+ 系统会自己路由到相册选择器 |
| **手机文件** | `ACTION_OPEN_DOCUMENT`，任意类型 |

面板做在 App 里而不是页面里，是因为**"字节从哪来"是设备问题，不是文档问题**：相机、相册、文件选择器都是 Android Activity，WebView 给不出一个统一的原生选择器。做在 App 里还顺带让它长得像系统，而不是像网页在模仿系统。

选完之后**上传本身完全走官方逻辑**，没有一行重写。

**三个曾经让「点上传没反应」的错，都已修**：

1. **被丢弃的回调**：页面在面板弹着的时候一直等一个文件选择结果。原来点「取消」、返回键、点面板外面
   都只是 `dismiss()`，**从不回调**，于是这次上传永远停在半路（下一次点「+」才会把上一次的结果当成
   null 收掉）。现在三条退出路径都会 `finishChooser(null)`。
2. **`CATEGORY_OPENABLE` 加错了对象**：它是 `ACTION_OPEN_DOCUMENT` 的要求，却曾被无条件加到相机 Intent
   上——带这个 category 的相机 Intent 在多数机器上匹配不到任何 Activity，于是每次都掉进 fallback。
3. **非法的 MIME 类型**：相册格子原来写的是 `setType("image/* video/*")`，而 `setType` 只接受单个
   MIME。现在用 `EXTRA_MIME_TYPES` 表达"两个都要"。

### 怎么知道手机上装的是哪一版

之前**没有答案**：APK 改过三次（去标题栏、修上传、加下载），`versionName` 一直是 1.0，
装完之后新包旧包分不出来——你问「我需要重装吗」，我答不上来。这是我的疏忽。

现在 App 会**自报版本**：启动时往 User-Agent 后面加一个 `PulseApp/<versionName>`，
自检面板把它读回来当第一行显示：

```
App: App 版本 1.2                                    ← 新版，带下载
App: 不在 App 里（浏览器），或是没有版本标记的旧 APK    ← 旧 APK，要重装
```

判据是**标记本身**：没有 `PulseApp/` 标记的一律是 1.2 之前构建的，也就是**没有下载能力**的那一版。
版本号只在 `AndroidManifest.xml` 一处，所以 Android 设置里看到的和面板里显示的永远一致。

| versionName | 内容 |
|---|---|
| 1.0 | 最初 |
| 1.1 | 去掉 ActionBar 黑边、上传三处修复 |
| 1.2 | 文件下载（DownloadListener + 进程内抓取）、自报版本 |
| **1.3** | **双指缩放可用**（原来被 `setSupportZoom(false)` 整个关掉了） |
| **1.4** | **图片交给手机自己的相册查看器**（适配 / 缩放 / 分享都由系统来做） |
| **1.5** | 文件列表加**转发**（`ACTION_SEND` → 系统分享面板 → 微信/QQ） |
| **1.6** | 图标换成官方鲸鱼标、名字改成 **DeepSeek** |
| **1.10** | 状态栏图标也换成鲸鱼、常驻通知压到最安静、弹窗写出项目名 |
| **1.11** | 锁定竖屏（不再跟着手腕转） |
| **1.12** | 平时不弹窗：子代理的回合不打扰，一轮结束后等 4 秒确认真的停了才弹 |
| **1.13** | 那条常驻通知可以划掉了，划掉之后**不会自己回来**（除非真有消息） |

### 图标：从运行中的客户端里取的官方标志

图标是**生成**的，不是手画的：`tools/make-icon.mjs` 读 `tools/whale-path.txt`，一次生成**两个**文件。

路径是**从运行中的客户端 DOM 里读出来的**（`viewBox="0 0 23.16 17.04"` 那个 svg 的唯一路径），
所以是真标志而不是照着重画。它是 3448 个字符的路径数据 —— **手抄一遍没有任何好处**，
掉一个数字就是一只长得微妙地不对的动物，而且不会有任何东西报错。

| 文件 | 画布 | 标志 | 用途 |
|---|---|---|---|
| `ic_launcher.xml` | 108×108 | 84×61.8，居中，黑鲸鱼 + 白圆角底 | 桌面图标 |
| `ic_notification.xml` | 24×24 | 20×14.7，居中，**白色鲸鱼、没有底** | 状态栏 / 通知头像 |

**为什么状态栏那个必须是另一张图**：Android 把通知的小图标当**遮罩**用 —— 每个不透明的像素
都会被涂成一个颜色。启动图标是一整块不透明的圆角方块，直接用会在状态栏糊成一个白方块
（这正是 v1.10 之前的状态：状态栏是一个**脉冲波形**，不是鲸鱼）。新的这张只有鲸鱼本身，
白色画在空白上，缩到 20dp 放在 24dp 画布里 —— 留在系统可能裁剪的 22dp 安全区以内。

渲出来核对过（`icon-notification-preview.png`）：**在 21:37 旁边 24px 处仍然一眼认得出是鲸鱼**，
浅色通知栏里是黑鲸鱼、深色状态栏里是白鲸鱼。

> 标志和名字是 DeepSeek 的品牌资产。自用没问题，**别分发**；手机上如果同时装了官方 DeepSeek App，
> 会出现两个同名图标。


### 看图片：为什么最后交给系统查看器

症状是"图片很大、不适配、也缩放不了"，而且**电脑上一样** —— 电脑上一样这一点就说明不是 App 的事。

查下去：官方客户端打开文件用的是 **`/api/file?path=...`**，而这个路由（`serveFile`）返回的是
**裸字节 + `Content-Type`，没有 `Content-Disposition`**。所以浏览器和 WebView 都把它当成一个
**顶层图片文档**来渲染 —— 而图片文档怎么适配、怎么缩放是**浏览器自己**的事，注入的 CSS 够不着
（我们的样式只进 `/` 那个页面，进不了一个图片文档）。这也解释了为什么先打开 `setSupportZoom`、
又加 `img { max-width }`，症状都没变。

**所以换思路：不让 WebView 当图片查看器。** 打开图片时（`shouldOverrideUrlLoading`，只对**导航**
触发，客户端里内联的 `<img>` 预览完全不受影响），App 用**同一个会话 cookie 和内置信任锚**把字节取到
缓存，再 `ACTION_VIEW` 交给系统相册 —— 适配、双指缩放、拖动、分享全都是系统原生能力。
文件经 `FileBridge` 的 `content://` 传递；provider 不导出，所以必须带
`FLAG_GRANT_READ_URI_PERMISSION`。

### 竖屏锁定

`android:screenOrientation="portrait"`。外壳的整套布局是**为竖屏写的**（抽屉、页头两行、
浮层夹回都按窄而高的视口算），横屏只是同一套东西的更差版本；用户的原话是"有时候手机侧过来
转一下，很难受"。锁定之后 WebView 也不会在手指底下重新排版。

### 缩放
`setSupportZoom(false)` 加 `setBuiltInZoomControls(false)` 曾经把缩放**整个关掉**。后果是官方查看器里
打开的图片**双指也放不大**，而它默认按原始尺寸显示，于是一张截图就是一堵像素墙。

现在 `setSupportZoom(true)`、`setBuiltInZoomControls(true)`、`setDisplayZoomControls(false)` ——
双指缩放可用，屏幕上不出现 +/- 按钮。配合 `lib/mobile-shell.js` 里一条只在手机宽度生效的
`img { max-width: 100% !important }`：只设上限、不设高度，所以不会跟有意设定尺寸的视图打架。

### 下载（把电脑上生成的文件存到手机）

**症状**：手机上看得到文件，但存不下来。

**根因在 App 这边**：`WebView` **完全没有下载能力**——页面跳到附件、或者点一个带 `download` 属性的
链接、或者在长按菜单里选「保存图片」，App 如果不装 `DownloadListener`，**什么都不会发生，也不报错**。
这个 App 之前就没装。

`Downloader.java` 补上这件事。**没有用系统的 `DownloadManager`**，两个原因：

1. `DownloadManager` 跑在系统的下载服务进程里，**不知道本 App 的 `network-security-config`**，
   而这个部署的证书是自签的——它会直接 TLS 握手失败。在 App 进程内抓取则自动继承那份内置信任锚。
2. 同理，它也拿不到 WebView 的会话 cookie，而 artifact 路由对未认证的调用一律 404。
   所以这里显式把 `CookieManager.getCookie(url)` 带上。

落盘位置：**API 29+ 写进真正的「下载」目录**（MediaStore，不需要任何权限，用 `IS_PENDING` 保证
半截文件不会出现在文件管理器里）；API 24–28 公开的下载目录需要 `WRITE_EXTERNAL_STORAGE`，
而这个 App **不申请任何存储权限**，所以退到 App 自己的外部目录，并且提示里**如实写明**去了哪里。

文件名优先从 URL 的 `path=` 参数取，而不是 `Content-Disposition`：这个服务器上的文件名基本是中文，
而 HTTP 头是 latin-1，中文文件名到头里会糊掉；URL 参数是百分号编码的 UTF-8，原样可解。

**另外查清楚了官方客户端这边**（`scripts/audit-download-path.mjs`）：把入口包、模块插件包、
它自己引用的 chunk 都读了一遍，**没有任何下载实现**——没有 `createObjectURL`、没有
`showSaveFilePicker`、没有 `download` 属性、没有处理 `Content-Disposition`。
所以官方界面里不存在一个"存到手机"的按钮，这不是漏点，是它本来就没有。
能存下来的入口是 Pulse 自己的界面 `/pulse`——那里的 artifact 列表每一条都带「下载」（真实 https URL）。

### 转发给微信 / QQ（两个 bug，不是一个）

手机上「转发」走的是系统分享面板（`ACTION_SEND` + `content://` URI），**踩了两个独立的坑**，
而且两个坑的症状**一模一样**（都是"发送失败"），所以第二个差点被当成第一个没修好：

**坑一：权限只挂在了 `EXTRA_STREAM` 上。** `FLAG_GRANT_READ_URI_PERMISSION` 只对
`getData()` 和 `getClipData()` 里的 URI 生效。只放 `EXTRA_STREAM` 的话，接收方（微信 / QQ 就是
这么读的）拿到的是一个它没有权限的 URI，于是显示"加载失败"。**"发送到我的电脑"能成**，是因为那条
路径根本没离开本 App。修法是把它同时放进 ClipData：

```java
send.putExtra(Intent.EXTRA_STREAM, uri);
send.setClipData(ClipData.newUri(app.getContentResolver(), file.getName(), uri));
send.addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION);
chooser.addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION);   // 选择器选中的那个也要拿到
```

**坑二：类型表把非图片文件谎报成图片。** 分享时告诉系统"这是什么"，**对方是信的**。
原来那张表只认 png/jpg/gif/webp/avif/bmp，**其余一律 `image/*`** ——
于是转发一个 `.md`、`.zip`、`.apk`，微信拿到一个声明为图片的 URI，试着解码，失败，
报"发送失败"。这跟权限 bug 的症状完全一样，所以第一次只修了权限是不够的。

现在是一张真表（`Mime.java`，41 个扩展名），未知扩展名一律
`application/octet-stream`（所有接收方都读作"一个文件"），**不再有任何东西被谎报成图片**。

这条是**可执行**的：`tools/check-mime.ps1` 在普通 JVM 上跑 30 项断言，
其中最关键的一条是**否定式**的——"任何非图片文件都不得被声明成 `image/*`"，
外加一条防止整张表退化成单一兜底的断言。把兜底改回 `image/*`，**2 项立刻变红**。

> 实话说清楚：这两个修法**都还没在真机上验证过**。分享面板是 Android 系统的东西，
> 这里跑不了。下一个 APK 装上去之后，请**转发一个非图片文件（比如 .md 或 .apk）给微信好友**
> 和**一张截图给 QQ 好友**各试一次 —— 前者验坑二，后者验坑一。

### 自检（因为选择器可能失配）

右下角一个小 **「?」**，点开显示：侧栏接管了吗、官方添加入口找到了吗、输入框找到了吗、当前视口宽度。

这个按钮是刻意加的。**选择器失配是这类改造最可能也最隐蔽的失败**——界面看起来"有点不对"，但不会报错。点「+」如果找不到官方入口，面板会**自动弹出**说明原因。

**它只存在于手机宽度**，所以电脑端看不到：外壳脚本是全局注入的，但样式只在 ≤900px 时显示这个按钮。

**它曾经关不掉**：面板 `z-index: 90` 铺在屏幕底部，而打开它的按钮是 `z-index: 50`——面板把唯一能关它的控件盖住了。现在按钮提到 `z-index: 95`（保持在面板之上），打开后自己变成 **×**；面板里另有一个「关闭」按钮；面板第一句就写明它是自检而不是功能按钮。

对应的验证是**对按钮中心做命中测试**：`document.elementFromPoint(按钮中心)` 必须命中按钮本身。
这条检查自带自检——先把 z-index 调回出 bug 时的关系，确认这条检查**会失败**；一条永远绿不了的断言等于没有。

### 没有标题栏

主题是 `@android:style/Theme.Material.Light.NoActionBar`。默认的平台主题会在 WebView 上面画一条
ActionBar，显示的正是 App 名字——结果是客户端自己的页头上面又压了一条黑边标题。用框架自带的
NoActionBar 主题就够，不需要新增任何资源文件（构建管线也就不必多一层）。

### 依赖：自己实现的 ContentProvider

拍照必须给相机一个 `content://` URI 去写文件（Android 7 起 `file://` 会抛 `FileUriExposedException`）。常规做法是 `androidx.core.content.FileProvider`，但这个 App **绕开 Gradle 构建**，没有 AndroidX。

所以 `FileBridge.java` 自己做这件事：只服务缓存下的**一个目录**，并拒绝任何解析后逃出该目录的路径——这条检查是关键，一个愿意打开任意路径的 provider 等于把 App 能读的所有文件都暴露出去。它不导出，只能通过拍照 Intent 上附带的一次性写权限访问。

另外**刻意不申请 `CAMERA` 权限**：一旦声明了它，`ACTION_IMAGE_CAPTURE` 就变成需要运行时授权；不声明则不需要。

## 安装

APK 在 `dist/pulse-remote.apk`（约 25 KB）。

**方式一：USB 调试**
```sh
adb install -r dist/pulse-remote.apk
```

**方式二：传到手机点开装**
把 `pulse-remote.apk` 用微信/QQ/数据线传到手机，用「文件管理」点开，允许「安装未知来源应用」。

首次打开会：
1. 请求通知权限 → **必须允许**，否则收不到任何提醒
2. 显示配对门禁页（如果你还没配对）

## 配对（只做一次）

在**电脑上**生成配对码：

```sh
cd dsh-remote-pulse
node scripts/pair-qr.mjs https://YOUR_HOST
```

然后手机 App 里填入那个配对码。配对成功后凭据存在 WebView 的 cookie 和 localStorage 里，
**重启 App、重启手机都不用再配对**。

## 后台保活（唯一的"折腾"，一次就好）

国内 ROM 会在息屏后杀掉后台进程，前台服务也不例外。**不做这一步，锁屏通知会时有时无。**

通用的两步：
1. 系统设置 → 应用管理 → **Pulse 遥控** → 省电策略 → 选 **无限制 / 允许后台运行**
2. 在最近任务里给这个 App **加锁**（下拉卡片点小锁图标，各家位置不同）

各家的具体路径：

| 品牌 | 路径 |
|---|---|
| 小米 / Redmi | 设置 → 应用设置 → 应用管理 → Pulse 遥控 → **省电策略 → 无限制**；再开「自启动」 |
| 华为 / 荣耀 | 设置 → 应用 → 应用启动管理 → Pulse 遥控 → 关掉「自动管理」，手动勾选**允许自启动 / 允许关联启动 / 允许后台活动** |
| OPPO / 一加 / realme | 设置 → 电池 → 应用耗电管理 → Pulse 遥控 → 允许**后台运行** + 允许**自启动** |
| vivo / iQOO | 设置 → 电池 → 后台高耗电 → 允许；i管家 → 应用管理 → 自启动 → 允许 |
| 三星 | 设置 → 电池 → 后台使用限制 → 从「休眠应用」里移除 |

设置完之后，App 会常驻一条「DeepSeek 已连接」的低优先级通知 —— **那条通知就是连接还活着的标志**。
如果它消失了，说明系统把服务杀了，回来做上面的设置。

## 通知是怎么来的

App 里有个前台服务，拿着配对时得到的会话 cookie，订阅 Pulse 的 `/api/stream`。

**一条通知，实时改写**：从回合开始到结束，服务把每一个 frame 都映射进那**同一条**常驻通知，
所以通知栏任何时候都能回答"它现在在干什么"，不用打开 App。映射规则本身就是全部逻辑：

| frame | 通知栏 | 弹窗提醒 |
| --- | --- | --- |
| `turn-start` 开始处理 | 「正在处理」+ 实时秒表 + 进度条 | **否**（电脑端开始跑的时候也不响） |
| `activity` / `summary` 工具调用 | 刷新那一行，秒表继续走 | **否**（否则每几秒嗡一次，人会开始无视这个通道） |
| `failure` 工具失败 | 「出错了」+ 原因 | **否**（失败后通常还会重试、然后回合结束，弹两次只为一件事） |
| `turn-end` 回合结束 | 摘要 + 最终答复正文（留在通知栏，直到下一回合覆盖） | **是**（就是这一下） |
| `decision` 等你决定 | 「等待你决定」+ 问题 | 否 —— 问题本身由 `decisions` 事件带着选项单独通知，不然会响两次 |
| `session` / 未知 kind | 不动 | 否（不认识的内容不猜：安静的漏报能补，半夜的误报收不回） |

**规矩只有一条：机器停下来的时候响一次。** 这一条是照电脑端抄的 —— `lib/index.js` 只在
`turn/end` 调 `pushNotification`，失败只有在 `notifyFailures` 打开时才推（默认关），
`turn/start` 从来不推。

### 「停下来」不等于「turn/end 到了」（v1.12）

手机上原来还是会被多余的弹窗打扰，原因有两个，都不是"哪一类 frame 该响"的问题：

**一、子代理的回合也发 turn/end。** 委派出去的子任务跑在自己的 session 里 —— 这台机器上
**13 个 session 里有 5 个是 depth 1** —— 每一个结束都会走同一条路，于是手机不断为一些用户
根本没要求知会的工作弹窗。现在 frame 上带了 `depth`（来自 session header 里那个不可变的
`delegationDepth`），**深度 > 0 的一律不打扰**，只是继续更新那一行。

**二、一轮结束不等于对话结束。** 回合结束之后如果紧接着又开始下一轮（目标轮次、agent 自己决定
继续做），那就是同一个任务中间喘了口气，弹"任务完成"是在骗人。所以完成提醒**延后 4 秒**发出，
期间**同一会话**又开始了新回合就**撤回**它。

这条规则本身没有时钟，所以被抽成了 `DoneGate.java`（和 `Notice.java` 一样零 Android 依赖），
`tools/check-notice.ps1` 直接跑它：

| 用例 | 期望 |
|---|---|
| 顶层回合结束 | 欠一次提醒 |
| 同一会话又开始了 | **撤回**那次提醒（不是完成，是还在跑） |
| 别的会话开始 | 这一条的提醒**仍然欠着**（别的对话与它无关） |
| 子代理回合结束 | 不欠任何提醒 |
| 提醒发出之后 | 不再欠 |

选择"哪种 frame 会响"仍然全在 `Notice` 里，而且判据从"数个数"改成了**列出形态**：

```
PASS 会打断的帧只有一种形态：turn-end@0（2 个用例覆盖它）
```

数个数在只有一种形态时够用，**列出形态才是在陈述规则** —— 以后谁再加一个会响的用例，
不可能悄悄把规则放宽。变异测试：把子代理那个分支去掉，这一行立刻变成
`[turn-end@0, turn-end@1]` 并失败。


秒表是**平台在走**（`setUsesChronometer`），从回合开始计时，几十秒没有新 frame 也不会看起来像卡死——
这是没有百分比可报时唯一诚实的进度信号。

**弹窗里会写明是哪个项目。** `task 完成` 这种话在两个会话同时开着的时候没有信息量，
所以 frame 上带了一个 `project`（工作区目录的最后一段，例如 `deepseek harness`，
来自会话自己的 `header.cwd`），**弹窗的标题就是它**，正文是那句摘要
（「任务完成 · 52秒 · 8 次工具调用」）。拿不到项目名时回落到通用措辞，不会瞎猜一个。

### 「没有消息的时候不要挂着」：能压到多安静

这条常驻通知**不能被去掉**，原因是平台的硬性规定而不是设计选择：**Android 8 起，后台要长期存活的
服务必须是前台服务，而前台服务必须有一条通知**。去掉它，息屏几分钟后 socket 就会被系统掐掉，
锁屏通知也就没了 —— 那正是这个 App 存在的理由。

所以能做的是把它压到不能再安静（v1.10 起）：

| 做了什么 | 效果 |
|---|---|
| 频道改成 `IMPORTANCE_MIN`（**新 id `connection`**，旧的 `stream` 启动时删掉） | 不响、不震、**不进状态栏**、折叠在通知栏最底部 |
| `setVisibility(VISIBILITY_SECRET)` | **不上锁屏** —— 你截图里那一条就属于这种情况 |
| **`setOngoing(false)` + 尊重划掉**（v1.13） | **可以划掉，而且划掉之后不再自己回来** |
| 内容相同就不再重发 | 不再每来一个 frame 就写一次通知 |
| 弹窗另走 `alerts` 频道（HIGH） | 真正要紧的那一下照样会响 |

**「为什么它一直活着？」** 因为前台服务必须有一条通知（平台规定），而第一版把它设成了
`ongoing` —— 那只意味着**用户划不掉**。现在改成可划掉，并且把"划掉"当作一个**回答**：

```
postedLine 已经发过 且 通知栏里找不到它 且 这次更新不是消息  →  说明用户划掉了
之后：闲置类更新一律不再发（不打扰）；任何真正的消息（回合开始 / 结束 / 待决策）会清掉这个
状态，通知照样回来
```

判断"划掉了"用的是 `NotificationManager.getActiveNotifications()`：系统没有提供回调，
只能在准备发下一条时顺便看一眼；读不到时按"还在"处理，免得某次读取失败变成通知永久消失。

所以正常使用的样子是：**用过一次之后把它划掉，通知栏就干净了**；等到我停下来或者需要你选择，
它会带着那条消息回来，你可以再划掉。

> 频道 id 为什么要换：**频道的重要性只能降、不能升，而且用户碰过之后就锁死了**。
> 旧的 `stream` 是以 `IMPORTANCE_LOW` 发布的，只要有人打开过通知设置，改代码也降不下来 ——
> 所以换新 id 是唯一可靠的做法，顺带把旧频道删掉，免得设置里留着两个开关。

如果你想要**一条常驻通知都没有**，那只有一条路：不要长连接，改成 App 定期醒来问一次
（比如每 15 分钟）。代价是通知最晚要等一个周期才到，而且息屏后系统可能进一步限制定时任务。
这个取舍我没有替你做，默认仍然是"实时但有一条极安静的通知"。

两条通道分开：进度走 `后台连接`（MIN、静音、不上锁屏），提醒走 `任务与决策`（会响）；
嫌吵可以只关后者。因为复用的是同一个会话 cookie，所以**在电脑上撤销这个设备，通知会立刻停**。

App 在前台时不会重复弹提醒（你已经在看了），但通知栏那一行照旧实时更新。

**这段策略不在 Android 回调里，而在 `Notice.java`**——一个没有任何 Android 依赖的纯映射，
所以它能被一条命令在普通 JVM 上跑完（见下）。这不是洁癖：上一版只处理了 `turn-end`、
把其它 frame 全部丢掉，于是整个任务期间通知栏一直是「Pulse 已连接」，
而这个 bug 在真机上花了很久才被看懂。**现在通知的落款也是 DeepSeek**：App 名字、通知标题、
证书安装对话框、电脑端 Web Push 的标题，全都不再出现 Pulse 这个只有开发者才知道的名字。

## 重新构建

工具链在 `D:\android-toolchain`（便携版，不污染系统）。改了指向的服务器或换了证书之后：

```powershell
cd pulse-android
# 1. 把新证书放到 app\res\raw\pulse_ca.crt
# 2. 改 build.json 里的 baseUrl
powershell -ExecutionPolicy Bypass -File build.ps1 -Clean
```

**指纹是构建时从内置证书现算的**（`tools/PinTool.java`），所以"内置的证书"和"代码里比对的指纹"
永远不可能对不上——那本来会是一个只在手机上才暴露的连接失败。

### 构建管线为什么不用 Gradle

APK 就是一个带清单、资源和 dex 的 zip，SDK 自带的工具足够直接拼出来：

```
aapt2 compile → aapt2 link（同时生成 R.java）→ javac → d8 → tools/pack.mjs → zipalign → apksigner
```

Gradle 会去 Maven Central 拉一整棵插件依赖树，对这个体量的项目来说又慢又容易失败。

三个已经踩过、都写进脚本注释的坑：

1. **项目路径带空格**（`D:\deepseek harness`），而 Windows PowerShell 5.1 调用原生 exe 时
   **不会自动加引号**，参数会被拆成两半。所以脚本全程用相对路径（不含空格），工具链放在无空格的绝对路径。
2. **javac 需要 `-encoding UTF-8`**：源码是无 BOM 的 UTF-8，否则 javac 按 GBK 解码，中文全变乱码。
   同时生成的 `Config.java` **必须不带 BOM**，否则 javac 在看到 `package` 之前先看到一个 U+FEFF 就拒绝。
3. **`resources.arsc` 必须是 STORED（未压缩）**，否则 targetSdk 30+ 的 App **安装直接失败**
   （`INSTALL_PARSE_FAILED_RESOURCES_ARSC_COMPRESSED`）。.NET 的
   `CompressionLevel.NoCompression` 其实是用 level 0 做 deflate，不是存储——所以
   `tools/pack.mjs` 自己读写 zip，逐条保留 aapt2 原本选的压缩方式。

## 已经静态验证过的

- 签名：APK Signature Scheme **v2 + v3** 通过（minSdk 24 不需要 v1）
- `resources.arsc` **STORED**，`zipalign -c 4` 通过
- 清单：包名 `com.pulse.remote`、minSdk 24、targetSdk 34、`networkSecurityConfig`、
  `foregroundServiceType="specialUse"` + 其 subtype 属性、通知权限齐全
- dex 里有 `com.pulse.remote.MainActivity` / `PulseService`
- 内置证书在 `res/raw/pulse_ca.crt`，与 `Config.CERT_PIN_SHA256` 由同一次构建算出
- **内置指纹与服务器当前实际证书逐字节一致**（不一致 App 会拒绝连接）
- 状态栏图标是独立的单色矢量图（鲸鱼本身，20×14.7 居中在 24×24 里）；通知小图标会被系统当作
  遮罩渲染成纯色，用有背景的启动图标会在状态栏糊成一个白方块 —— 这正是它为什么要单独生成
- 常驻通知走 `IMPORTANCE_MIN` + `VISIBILITY_SECRET`：不进状态栏、不上锁屏；旧的 `stream`
  频道在启动时删除，避免设置里留下第二个开关
- **通知策略是可执行的**：`powershell -ExecutionPolicy Bypass -File tools\check-notice.ps1`
  用真实 frame（kind 和文案都照抄 `dsh-remote-pulse/lib/distill.js`）驱动 `Notice.of` 和
  `DoneGate`，31 项断言，包括"工具调用不弹窗""秒表不重置""回合结束后迟到的 frame 不覆盖摘要"
  "弹窗标题用项目名、拿不到时回落到通用措辞""子代理的回合不打扰"
  "同一会话又开始了就撤回那次提醒、别的会话开始不撤"，
  以及一条全局断言：**会打断的帧只有一种形态 `turn-end@0`**（决定由 `decisions` 事件
  单独提醒，所以它在 `Notice` 里不许再响一次）。
  这条检查**自带自检**：把 activity 分支改回"直接丢弃"，6 项立刻变红、退出码 1——
  一条永远绿的断言等于没有。它同时兜住那个"所有 case 都期望 null"的退化
  （末尾断言至少产生过一条通知）。
- **转发用的类型表是可执行的**：`powershell -ExecutionPolicy Bypass -File tools\check-mime.ps1`
  在普通 JVM 上跑 30 项断言（`Mime.java` 无 Android 依赖）。核心是一条**否定式**断言：
  任何非图片文件都不得被声明成 `image/*`；末尾还有一条防止整张表退化成单一兜底的断言。
  把兜底改回 `image/*`，立刻变红。

## 还没验证的（需要真机）

静态检查证明不了运行期行为，以下是必须在你手机上过的：

- [ ] 能装上、能打开、官方界面正常显示
- [ ] 界面里的实时更新正常（官方界面靠 WebSocket；自签证书 + WebView 的组合在这里是最需要盯的一点）
- [ ] 配对成功后重启 App 仍然是登录态
- [ ] 电脑上让 agent 需要授权 → 手机锁屏能收到通知
- [ ] 后台保活设置生效（息屏 10 分钟后仍然在线）
- [ ] 电脑上跑一个长任务 → 那条常驻通知的**标题和那一行真的在变**，秒表在走，不再只是一句「已连接」
- [ ] 开始跑的时候**不响**，停下来的时候响**一次**（工具调用的中间过程也不响）
- [ ] 弹窗上写的是**项目名**（工作区目录名），正文是那轮摘要
- [ ] 锁屏上**看不到**「DeepSeek 已连接」那条常驻通知（`VISIBILITY_SECRET`）
- [ ] 通知栏里它折叠在最底部、没有状态栏图标、不响（`IMPORTANCE_MIN`）
- [ ] 分享给微信 / QQ 好友能发出去（两个坑：`ClipData` 那条修复，以及类型表不再把非图片
      谎报成 `image/*`；只挂 `EXTRA_STREAM` 时「我的电脑」能收到而「发送给好友」会报"加载失败"）
- [ ] **转发一个非图片文件**（.md / .zip / .apk）给微信好友 —— 这一条验的是类型那个坑
- [ ] **转发一张截图**给 QQ 好友 —— 这一条验的是权限那个坑

如果第 2 项不过（界面能开但内容不更新），说明 WebView 对自签证书的 WebSocket 没有走 App 里配置的
信任链。**退路已经准备好了，三步，不用重新构建 App：**

1. 手机浏览器打开 **`https://YOUR_HOST/pulse-ca.crt`**
   （会弹一次证书警告，点「高级 → 继续前往」；这是正常的，正是因为手机还不信任它，才需要这一步）
2. 下载完点开它，系统会问「安装证书」→ 选 **CA 证书** → 确认
   （路径：设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书。**会要求先设一个锁屏密码**）
3. 回到 App 重开

这样证书进入手机的用户凭据库，WebView 自己就会信任它。App 自己的长连接仍然走内置证书那条更严格的
路径，不受影响。

## 两个环境限制

- **只有 443 端口从公网可达**（80 和 8443 被腾讯云安全组挡着）。所以对外的一切都得走 443。
- **没有开机自启**：重启手机后需要**手动打开一次 App**，前台服务才会重新建立连接。这是刻意的取舍——
  Android 12+ 对开机广播启动前台服务有限制，加了 receiver 反而可能是崩溃而不是收益。
